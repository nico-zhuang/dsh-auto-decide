# dsh-auto-decide

DSH 0.2.1-rc.2 的普通 `ask_user_question` 超时处理插件：默认启用、全局模式、120 秒后跳过；可在「插件 → 已安装插件 → dsh-auto-decide → 组件配置」修改为 1–3600 秒（例如 5 秒）、切换为唯一推荐项模式，或限制到指定会话。配置由 DSH Config Forms 持久化，升级旧版会保留全局行为。

## 会话范围

- **全局（默认）**：所有当前和以后新建的会话都使用插件，兼容 0.1.1 原有行为。
- **白名单**：仅在勾选并保存的会话生效；新会话默认不在名单中，空名单表示全部由用户回答。推荐项模式优先使用白名单。
- **黑名单**：勾选并保存的会话始终由用户回答，其余会话生效；以后新建的会话也会生效，空名单等同全局。请特别注意重要的新会话。

组件配置中先选工作范围，再展开「选择会话」，按标题或 ID 搜索、多选并单击「保存名单」。可显示已归档会话；名单只保存稳定会话 ID，不按可变标题匹配。已选但目录不再显示的会话可从名单中移除。模式或名单在一个问题等待期间变更时，旧计时器不会沿用先前规则自动作答；不在范围内的普通问题从一开始交由原本人工应答界面处理。全局模式仍保留已保存的名单，切回白/黑名单时恢复。

设置页不重复插件管理器的标题和简介；关键选项集中在紧凑卡片里，较长的范围与安全说明默认收起。全部插件自绘文案订阅 DSH `locale` 服务，随「设置 → 常规」的中文／英文选择即时切换；颜色和圆角跟随 DSH 的明暗主题变量。v0.2.3 在设置摘要明确显示已开启／已暂停，白名单为空时注明未覆盖任何会话；选择推荐或跳过的规则未变。

## 历史加载风险与 v0.2.2 修复

**不要继续使用 v0.2.1 触发自动回答。** 旧版在 `agent.inject()` 中传入了缺少 `id` 和 `role` 的消息，DSH 0.2.1-rc.2 可能允许它写入持久会话，但重新加载时会拒绝这类 `user/message`。v0.2.2 在注入前生成唯一消息 ID 并明确设置 `role: 'user'`，保留 `source.kind: 'dsh-auto-decide'` 与内容中的 `humanConfirmed: false`。这只防止**新的**不合格注入，**不会自动修复已经打不开的会话**。

如果旧会话加载失败，先在所有设备停用插件，完整保存原始会话文件；不要删除中间事件、修改会话压缩包或清理索引来碰运气。针对确切报错另行备份、诊断并在停止 DSH 写入时测试副本，经过会话所有者确认后才考虑对原件做可审计恢复。

## 处理范围与安全边界

- `skip`：整批普通问题到时都返回 `{selected:[]}`；**跳过不是同意**。
- `recommended`：**仅对题干和推荐选项均明确属于展示／外观／格式／语言类**的单选题匹配标签末尾唯一的 `(Recommended)`；陌生领域、多选、缺失/重复推荐项或涉及部署、发布、删除、支付、授权、同意、分享、发送、写入等敏感动作时一律回退跳过。不猜测第一个选项，也不提供通用自动批准。
- 仅处理来自模型工具 `ask_user_question` 且属于确切 live agent 的请求。带 `intent`/`detail` 的计划审阅和独立的安全审批渠道不会自动应答。真人抢先回答时优先真人；插件停用或等待中改配置后不沿用旧自动规则。
- 自动结果在下一步 Agent 上下文明确标记插件来源、`humanConfirmed: false`、选择与“跳过非同意”。不伪装为用户对外操作的授权。

**限制：**敏感词过滤不是语义安全审查；推荐模式需使用者主动启用。Host 自行计时，与 DSH `timed` 问题策略不同；更短的宿主定时器或直接关闭插件可能改变结果。插件不会代替用户处理计划审阅或安全审批。

## 安装、测试与回滚

通过 DSH 侧栏「插件 → 添加插件」安装已发布 GitHub 标签 `github:nico-zhuang/dsh-auto-decide#v0.2.3`；按安装器提示启用。已有旧版时，桌面内置 `dsh plugin --profile desktop add 'github:nico-zhuang/dsh-auto-decide#v0.2.3'` 可原位更新并固定标签、保留设置，不手工修改 profile 文件。若提示重启，须重启当前桌面宿主，单纯刷新浏览器不够。安装后从组件配置页核对开关、范围、名单、模式和秒数，再用普通无风险问题确认推荐、回退跳过和来源说明。测试不可用真实发布、删除或支付操作。

本地使用 Node 24 测试发布门禁：

```bash
npm install --ignore-scripts --no-audit --no-fund --no-package-lock
npm run test:release
```

`test:release` 依次运行语法检查、单元测试以及 DSH 0.2.1-rc.2 的真实 v4 Zstd 会话写入、关闭与冷重载，分别校验插件实际生成的跳过和推荐消息。测试脚本会将精确版本的 Host 依赖安装在系统临时目录，完成后清理；无需设置 `DSH_HOST_DEPS`，不访问真实用户会话或安装 profile。任一检查失败时命令非零退出；**发布者必须在打标签和发布前运行 `npm run test:release` 并确认成功**。当前仓库尚未启用 GitHub 自动 CI，不能把本地发版检查误称为远端强制门禁。仅做快速开发检查可分别运行 `npm test` 和 `npm run check`。

回滚请使用 DSH 插件管理器先停用或卸载 `dsh-auto-decide`，不手工修改 profile 清单、Cordis patch 或应用包。
